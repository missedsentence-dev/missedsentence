# 놓친문장

**운전이 복잡해지는 순간이 오기 전에 문장이 끝나는 자리에서 말소리를 잠깐 쉬고, 지나가면 이어서 들려주는 Pleos Connect 차량용 오디오 앱**

오디오북, 강의, 어학 문장을 들으며 운전하다 보면 좌회전, 합류, 우회전 앞 횡단보도 같은 순간에 방금 들은 문장을 놓칩니다.
놓친문장은 내비의 회전 안내와 차량 신호로 그 순간을 미리 알고, 문장 중간이 아니라 문장이 끝나는 자리에서 쉽니다.
순간이 지나가면 다음 문장부터, 중간에 끊었다면 그 문장 처음부터 다시 들려줍니다.
볼륨을 낮추지 않고, 주행 중 화면에 글을 띄우지 않고, 다른 앱의 소리를 건드리지 않습니다.

## 주요 기능

| 기능 | 설명 | 사용한 API |
|---|---|---|
| 닿기 전에 미리 미룸 | 좌회전, 유턴, 합류, 진출 10초 전에 문장이 끝나는 자리에서 쉼. 4초 안에 문장이 끝나지 않으면 끊고 나중에 그 문장 처음부터 | NaviHelper 회전 안내, AAOS 속도 |
| 신호 대기 중 다시 재생 | 회전 전에 5초 넘게 서 있으면 다시 들려주고, 브레이크에서 발을 떼는 순간 끊음 | AAOS 속도, Vehicle SDK Brake |
| 보행자와 만나는 순간 | 우회전 6초 전과 어린이보호구역에서는 민감도와 상관없이 항상 쉼 | NaviHelper 회전 안내와 주의 지점과 제한속도, Vehicle SDK TurnSignal |
| 차로 변경 예산 | 차로 변경은 30분에 2번까지만 멈추고, 그 뒤로는 멈추지 않고 그 문장을 다시 들을 문장에 남김 | Vehicle SDK TurnSignal, AAOS 속도와 조향각 |
| 기본 모드 | 길안내가 없을 때는 방향지시등을 켠 순간의 속도로 회전과 차로 변경을 가름 | Vehicle SDK TurnSignal, AAOS 속도와 조향각 |
| 급제동 반응 | 1초에 시속 12km 넘게 줄면 끊고, 3초 잦아들면 그 문장 처음부터 | AAOS 속도 |
| 안내 음성 때 멈춤 | 내비 안내 음성이 나오면 멈췄다가 끝나면 그 문장 처음부터 | Android 오디오 포커스 |
| 핸들 이전 버튼 | 이전 버튼을 한 문장 다시 듣기로 받음 | Android MediaSession |
| 차량 미디어 화면 연동 | 주행 중에는 앱 화면 대신 차량 미디어 화면에 제목, 쉬는 이유 한 줄, 문장 수로 채우는 진행 막대를 보여 주고, 묶음 목록을 오디오북과 어학으로 나눠 제공 | Android MediaBrowserService, MediaSession |
| 다시 들을 문장 | 어학 묶음은 다음 출발 때 그 문장부터 자동으로 이어 듣고, 이야기 묶음은 정차 화면에서 앞뒤 문장과 함께 다시 들음 | 앱 내부 |
| 정차 화면 | 기어 P이고 주행 규제가 풀렸을 때만 콘텐츠 선택, 민감도, 오늘 멈춘 이유, 다시 들을 문장을 보여 줌 | AAOS 기어, CarUxRestrictions |
| 출발 제안 | 평일 아침에 회사로 안내 시작 버튼을 보여 줌 | NaviHelper 즐겨찾기, 길안내 요청 |
| 지원 확인 | 시작할 때 방향지시등, 브레이크 페달, 조향각을 쓸 수 있는지 확인해 화면에 보여 주고, 없는 신호의 규칙은 끔 | Vehicle SDK 기능별 지원 확인 |

### 멈춤 규칙

| 분류 | 신호 | 언제 | 동작 | 다시 재생 |
|---|---|---|---|---|
| 보행자 | 우회전 | 회전 지점 6초 전. 기본 모드는 방향지시등을 시속 25km 이하이거나 감속 중에 켤 때 | 문장 사이에서 미룸. 4초 안에 안 끝나면 끊음 | 회전 뒤 조향 안정 2초 |
| 보행자 | 어린이보호구역 | 구역에 들어가기 6초 전부터. 들어가는 순간에 알면 바로 | 미룸 또는 끊음 | 구역을 벗어났다는 판정이 올 때만 |
| 복잡한 회전 | 좌회전, 유턴, 합류, 진출 | 보통 10초 전, 낮음 8초 전 | 문장 사이에서 미룸. 4초 안에 안 끝나면 끊음 | 회전 안내가 다음 단계로 넘어가고 조향 15도 이하 3초 |
| 복잡한 회전 | 신호 대기 | 회전 전에 5초 넘게 서 있음 | 서 있는 동안 다시 재생 | 브레이크에서 발을 떼는 순간 끊고, 회전 뒤 그 문장 처음부터 |
| 예산 | 차로 변경 | 방향지시등을 시속 40km 이상에서 켤 때. 그 사이 속도면 10초 안에 조향이 크게 꺾일 때 회전으로 다시 분류 | 끊음. 예산은 30분에 2번, 간격 90초 | 꺼지고 2초 뒤 그 문장 처음부터 |
| 안전 반응 | 급제동 | 1초에 시속 12km 넘게 감속 | 끊음 | 3초 잦아들면 그 문장 처음부터 |
| 기본 준수 | 내비 안내 음성 | 오디오 포커스를 잠시 잃음 | 멈춤 | 안내가 끝나면 그 문장 처음부터 |

- 다음 멈춤이 30초 안에 시작될 것 같으면 다시 틀지 않고 이어서 쉽니다.
- 어린이보호구역이 아닌 멈춤은 차가 움직인 시간 기준 60초에서 풉니다.
- 민감도는 보통과 낮음 두 단계입니다. 낮음은 복잡한 회전을 8초 전에 미루고 차로 변경에서는 멈추지 않습니다. 우회전과 어린이보호구역은 어느 단계에서나 같습니다.
- 미룰 때는 오디오 포커스를 쥔 채 재생만 멈춥니다. 그 사이에 라디오가 끼어들지 않습니다.

### 두 모드
- **경로 모드**: 차량 기본 내비로 길안내 중일 때. 회전 안내의 종류와 남은 거리로 미리 미룹니다.
- **기본 모드**: 길안내가 없을 때. 방향지시등을 켠 순간의 속도와 조향으로 판단합니다. 미리 알 수 없어 중간에 끊기는 일이 늘어나므로 출발 제안으로 길안내를 권합니다.

### 어린이보호구역 판정 순서
1. NaviHelper 주의 지점 이벤트에 어린이보호구역을 가리키는 값이 오면 그 값으로 판정합니다.
2. 그 값이 없으면 공공데이터의 보호구역 좌표와 현재 위치의 거리 300m 이내, 그리고 제한속도 30 이하를 함께 봅니다.
3. 둘 다 쓸 수 없으면 이 규칙을 끕니다. 정차 화면의 지원 확인 결과에 지금 어느 단계인지 나옵니다.

공공데이터 좌표 파일은 저장소에 넣지 않았습니다. 넣는 법은 아래 '어린이보호구역 좌표 넣기'에 있습니다.

### 사용하는 차량 데이터와 개인정보
- **Pleos Vehicle SDK**: TurnSignal, Brake, SteeringWheel 도메인만 읽습니다. 기능마다 지원 확인을 먼저 부르고, 지원하는 항목만 조회합니다.
- **AAOS Car API**: 속도, 기어, 조향각, 주행 규제 상태
- **NaviHelper SDK**: 회전 안내, 주의 지점, 도로 제한속도, 현재 위치, 즐겨찾기, 최근 목적지, 길안내 요청
- 차량 제어 권한과 네트워크 권한을 쓰지 않습니다.
- 위치는 어린이보호구역 좌표와 비교하는 데만 메모리에서 쓰고 저장하지 않습니다. 기기에 남는 것은 듣던 자리, 다시 들을 문장 번호, 멈춘 이유의 종류와 횟수뿐입니다.

## 실행 방법

### 1. 개발 환경
- Android Studio 최신 버전, Gradle용 JDK는 17 또는 21. 최신 Android Studio에 들어 있는 JDK 25는 Gradle 8.10.2와 맞지 않으므로 **Settings → Build Tools → Gradle → Gradle JDK**에서 21을 고릅니다. 목록에 없으면 같은 칸의 Download JDK로 받습니다.
- Pleos Connect Emulator v2.1.0, Android 14 API 34 시스템 이미지
- Gradle 8.10.2, Android Gradle Plugin 8.8.2, Kotlin 2.0.0
- minSdk 33, compileSdk와 targetSdk 35
- 의존성: `ai.pleos.playground:Vehicle:2.3.2`, `ai.pleos.playground:NaviHelper:3.0.5`. 그 밖의 외부 라이브러리는 쓰지 않습니다.

### 2. 에뮬레이터 준비
1. Android Studio **SDK Manager → SDK Update Sites**에 아래 주소를 추가합니다.
   - Windows, Linux: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
   - Mac: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml`
2. **SDK Platforms → Android 14, API 34 → Pleos Connect System Image**를 설치합니다.
3. **Device Manager → Automotive → Pleos Connect v2.1.0**으로 AVD를 만들고 Cold boot, RAM 4GB로 설정합니다.

### 3. 빌드와 설치
```bash
./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb install -r navprompt/build/outputs/apk/release/navprompt-release.apk
```
Windows에서는 `.\gradlew.bat assembleRelease` 를 씁니다.
Windows에서 가상 차량을 켜 둔 채로 아래 한 줄을 실행하면 빌드, 설치, 실행, Virtual Console 연결까지 한 번에 합니다.
```
powershell -ExecutionPolicy Bypass -File scripts\build-run.ps1
```
Android Studio에서는 이 폴더를 열고 실행 대상에서 `app` 을 고른 뒤 Pleos 에뮬레이터에서 Run을 누르면 됩니다. 시연용 안내 음성 앱은 실행 대상을 `navprompt` 로 바꿔 한 번 더 Run을 누릅니다.
처음 실행할 때 속도 정보와 알림 권한을 허용해 주세요.

Windows용 스크립트는 다음과 같습니다. 모두 `powershell -ExecutionPolicy Bypass -File scripts\이름.ps1` 로 실행합니다.

| 스크립트 | 하는 일 |
|---|---|
| `start-car.ps1` | Android Studio를 켜지 않고 가상 차량만 켬. PC가 느릴 때 씀 |
| `build-run.ps1` | 빌드, 설치, 권한 허용, 실행, Virtual Console 연결. 끝에 `-SkipBuild` 를 붙이면 설치와 실행만 |
| `make-apk.ps1` | 제출용 설치 파일 두 개를 만들어 `apk` 폴더에 모음 |
| `collect-info.ps1` | 에뮬레이터에서 화면과 차량 값을 단계별로 모아 묶음 파일로 만듦 |

## 테스트 환경 및 필요한 설정

### Virtual Console로 차량 상태 바꾸기
```bash
adb forward tcp:8088 tcp:8088
```
브라우저에서 `http://127.0.0.1:8088/` 을 열면 기어, 가속과 브레이크 페달, 방향지시등, 조향각을 바꿀 수 있습니다. 앱은 이 값을 그대로 읽습니다.

### 주행 중 화면과 차량 미디어 화면
Pleos Connect Emulator v2.1.0 이미지에서는 기어가 P가 아니면 직접 설치한 앱의 화면이 "주행 중에는 사용할 수 없습니다" 화면으로 가려집니다. 화면에 주행 중 사용 선언(distractionOptimized)을 넣어도 마찬가지였습니다.
놓친문장은 이 조건에서도 쓸 수 있게 만들었습니다.
- 재생과 멈춤 판단은 화면이 아니라 미디어 재생 서비스에서 돌아가므로, 화면이 가려져도 소리와 문장 미루기는 그대로 이어집니다.
- 주행 중에 보여 줄 내용은 `MediaBrowserService` 와 `MediaSession` 으로 차량 미디어 화면에 넘깁니다. 제목은 묶음 이름, 둘째 줄은 쉬는 이유("좌회전이 끝나면 이어서 들려줘요" 같은 한 줄), 진행 막대는 문장 수입니다.
- 앱의 주행 화면은 정차 화면 시연 도구의 **주행 화면 미리보기**와 시연 장면에서 볼 수 있습니다.
- 차량이 화면을 가린 동안에는 보이지 않는 화면을 고쳐 그리지 않습니다. 에뮬레이터처럼 느린 기기에서 화면 그리기가 밀려 앱이 멈춘 것으로 처리되는 일을 막기 위해서입니다.
- 에뮬레이터에서 화면과 차량 값이 어떻게 보이는지 한 번에 모으려면 `scripts/collect-info.ps1` 을 실행합니다.

### 시연 도구
에뮬레이터에서 길안내를 켠 주행은 확인하지 못했습니다. 그래서 앱 안에 정해 둔 출근길을 달리는 작은 주행 모형을 넣었습니다.
이 모형이 만든 속도, 회전 안내, 어린이보호구역 주의 지점, 제한속도는 실제 이벤트가 들어오는 통로와 같은 통로로 들어갑니다. 방향지시등, 브레이크, 조향, 기어는 Virtual Console 값이 함께 쓰입니다.
시연 모드에서는 화면에 '시연' 표시가 붙고, 주행 화면에 신호와 동작을 한 줄씩 보여 주는 띠가 나옵니다.
시연 모드에서는 차량 값이 제대로 읽히는지 확인할 수 있도록 기어, 속도, 방향지시등, 브레이크, 재생 상태를 1초마다 기기 기록(logcat, 태그 MissedSentence)에 남깁니다. 위치와 콘텐츠 내용은 남기지 않습니다.

정차 화면의 **시연 도구**에서 할 수 있는 일은 다음과 같습니다.

| 도구 | 하는 일 |
|---|---|
| 장면: 좌회전과 신호 대기 | 약 50초. 회전 전 미룸, 신호 대기 중 다시 재생, 출발 순간 끊음, 회전 뒤 재생 |
| 장면: 어린이보호구역 | 약 50초. 구역에 들어가기 전 미룸, 벗어나면 재생 |
| 장면: 우회전과 보행자 대기 | 약 40초. 우회전 전 미룸, 회전 뒤 재생 |
| 장면: 출근길 전체 | 약 2분 50초. 위 세 장면을 30초 넘게 띄워 이어 붙임 |
| 비교: 규칙 끔 | 휴대폰을 블루투스로 연결해 들을 때처럼 어떤 순간에도 계속 재생 |
| 가상 속도 | 기본 모드 장면용. 시속 20에서 방향지시등을 켜면 회전, 시속 60에서 켜면 차로 변경으로 판단 |
| 주행 화면 미리보기 | 기어를 바꾸지 않고 주행 화면을 봄 |
| 처음 문장부터 다시 찍기 | 처음 문장으로 돌아가고 오늘 기록, 다시 들을 문장, 차로 변경 예산을 비움 |
| 내비 원문 기록 | NaviHelper에서 받은 회전 안내, 주의 지점, 제한속도의 원문을 보여 줌. 위치는 남기지 않음 |

신호 대기 장면에서 Virtual Console의 브레이크 페달을 밟고 있으면 차가 더 기다리고, 떼는 순간 출발하며 말소리가 끊깁니다.

### 핸들 이전 버튼과 안내 음성
- 핸들의 이전 버튼은 `adb shell input keyevent 88` 로 대신합니다. `scripts/media-previous.ps1` 에 넣어 두었습니다.
- 안내 음성은 따로 만든 작은 앱 `navprompt` 가 대신합니다. 내비 안내 용도로 오디오 포커스를 4초 동안 요청하고 안내음을 냅니다. 앱을 열어 버튼을 누르거나 `scripts/nav-prompt.ps1` 을 실행합니다.
- 실제 속도 값으로 기본 모드를 보려면 Virtual Console의 가속 페달로 속도를 올립니다. 정해진 값을 바로 넣는 `scripts/real-speed.ps1 -Kmh 60` 은 잠금 상태가 아닌 에뮬레이터 이미지에서만 동작합니다.

### 에뮬레이터 없이 하는 점검
```bash
tools/check.sh
```
PC의 JVM에서 세 가지를 검사합니다. kotlinc와 JDK 17 이상이 있으면 됩니다.

| 검사 | 대상 | 항목 수 |
|---|---|---|
| 엔진 시나리오 검사 | 멈춤 규칙 `core/LoadEngine.kt`. 주행 장면을 0.2초 간격으로 흘려 넣어 결정이 맞는지 확인 | 109 |
| 재생기 검사 | 문장 재생기 `player/SentencePlayer.kt`. 문장 사이 미룸, 끊고 처음부터, 오디오 포커스, 이전 버튼, 이어 듣기, 차량 미디어 화면에 알리는 내용 | 67 |
| 앱 흐름 검사 | `Controller.kt` 와 엔진, 재생기, 묶음 읽기를 이어서. 시연 장면 네 개, 기본 모드, 다시 들을 문장, 정차 요약, 저장, 차량 미디어 화면에서 온 재생 요청, 화면이 가려진 상태 판정 | 92 |

재생기 검사와 앱 흐름 검사는 실제 소스를 그대로 쓰고, Android 클래스만 `tools/playertest/fake` 의 가짜로 바꿔 가짜 시계로 시간을 흘려보냅니다. 소리가 실제로 나는지와 화면은 에뮬레이터에서 확인해야 합니다.

## 콘텐츠와 음성 출처

| 묶음 | 글 | 소리 |
|---|---|---|
| 출근길 영어 문장, 24문장 | 이 앱을 위해 직접 쓴 문장 | Piper로 합성. 음성 모델은 en_US-ljspeech-medium |
| 출근길 이야기, 14문장 | 이 앱을 위해 직접 쓴 글 | 소리 파일 없음. 기기의 음성 합성으로 읽고, 없으면 소리 없이 시간만 흐름 |
| 직접 녹음한 낭독 | 글을 넣지 않음 | 직접 녹음한 파일을 문장별로 나눠 넣는 자리. 비어 있는 동안에는 앱 목록에 보이지 않음 |

- Piper는 MIT 라이선스의 음성 합성 프로그램입니다. `https://github.com/rhasspy/piper`
- 음성 모델 en_US-ljspeech-medium 의 모델 카드에는 학습 데이터가 LJ Speech이고 라이선스가 public domain 이라고 적혀 있습니다. 모델은 `https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-piper-en_US-ljspeech-medium.tar.bz2` 에서 받았습니다.
- 만드는 과정은 `tools/build_english_pack.py` 에 그대로 있습니다. 앱에는 합성한 소리 파일만 들어 있고 합성 프로그램과 모델은 들어 있지 않습니다.
- 다른 사람이 쓴 작품의 글은 어떤 파일에도 넣지 않았습니다.

### 직접 녹음을 넣는 법
1. 조용한 곳에서 문장과 문장 사이를 1초 넘게 쉬며 녹음합니다.
2. 어떻게 잘리는지 먼저 봅니다. `python3 tools/split_recording.py 녹음.m4a --list`
3. 잘못 읽어 다시 읽은 조각의 번호를 빼고 만듭니다. `python3 tools/split_recording.py 녹음.m4a --title "낭독 제목" --drop 3,7`
4. 앱을 다시 빌드하면 콘텐츠 목록 맨 앞에 나타납니다.

ffmpeg가 있어야 합니다. 이 도구는 소리만 다루며 글은 넣지 않습니다.

### 어린이보호구역 좌표 넣기
1. 공공데이터포털에서 전국어린이보호구역표준데이터를 CSV로 내려받습니다.
2. 위도와 경도 열이 들어 있는 그대로 `app/src/main/assets/zones/school_zones.csv` 로 저장합니다. 첫 줄의 열 이름에 위도와 경도가 있으면 읽습니다. 파일은 UTF-8로 저장합니다.
3. 앱을 다시 빌드합니다. 주의 지점 값이 오지 않는 차에서도 좌표와 제한속도로 판정합니다.

## 알려진 한계
- 실제 차량에서는 확인하지 못했습니다. 확인은 모두 Pleos Connect 에뮬레이터에서 했고, 자세한 내용은 `docs/emulator_check.md` 에 있습니다.
- 에뮬레이터에서 길안내를 켠 주행은 확인하지 못해 시연에서는 주행 모형이 회전 안내와 속도를 대신 넣습니다. 실제 차에서는 같은 통로로 NaviHelper 이벤트가 들어옵니다.
- 에뮬레이터는 기어가 P가 아니면 직접 설치한 앱의 화면을 가립니다. 주행 중 표시는 차량 미디어 화면에 맡기도록 만들었지만, 에뮬레이터의 미디어 화면에 표시되는 모습은 확인하지 못했습니다. 앱의 주행 화면은 주행 화면 미리보기와 시연 장면으로 보여 줍니다.
- 회전 안내와 주의 지점 자료형의 필드 이름은 이름이 비슷한 항목을 찾아 읽습니다. 읽지 못하면 그 길에서는 기본 모드 규칙으로 판단하고, 받은 원문은 시연 도구의 내비 원문 기록에 남습니다.
- 한국어 묶음은 직접 녹음을 넣기 전까지 기기의 음성 합성에 기대며, 음성 합성이 없으면 소리 없이 진행만 됩니다.
